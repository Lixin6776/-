# CDP Live Monitor Runbook

第一版以 CDP 作为过渡方案，优先保证只读监控可用。

## 启动顺序

1. 使用登录了目标千川账号的 Chrome/Edge。
2. 保持 CDP 地址为 `http://127.0.0.1:9222`，不要把端口暴露到公网。
3. 在浏览器中打开目标直播间的“直播大屏”，页面 URL 需要包含 `board-next`。
4. 启动本地后端和前端。
5. 打开 `http://127.0.0.1:5173`，确认“计划与直播间”面板显示 `CDP`、数据新鲜度和核心指标。

## 监控配置

```powershell
$env:QCA_MONITOR_SOURCE = "cdp"
$env:QCA_MONITOR_INTERVAL_SECONDS = "300"
$env:QCA_LIVE_BOARD_PAGE_MARKER = "board-next"
```

- `300` 表示 5 分钟。
- 如需降低频率，可改为 `600`，即 10 分钟。
- API 凭据可以保持为空，第一版不会因此切换掉 CDP 监控。

## 当前读取指标

- 综合成本
- 综合营销 ROI
- 净成交金额
- 整体成交订单数
- GPM
- 实时在线人数
- 直播间整体观看人数

## 失败处理

- 找不到直播大屏：事件标记为 `cdp-error`，数据新鲜度为 `stale`。
- 页面字段变化：事件暂停判断，`reason` 显示读取失败原因，不触发自动写入。
- 页面失效、登录过期或出现风控提示：停止操作，等待用户人工处理。
- 不把样例数据伪装成真实数据；读取失败时显示异常状态。

## 边界

- 第一阶段只做读取、分析、提醒和人工确认。
- 写入动作仍需要选择器校准和确认流程。
- 任何账户修改都必须在用户明确确认后执行。
